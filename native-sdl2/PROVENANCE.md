# Native source and asset provenance

The artwork is Godog by Komplex (1998). Its recovered classes and assets remain
in `original/`, with independent decompiler output in `reverse/`. The runnable
Java reference is `java-desktop/`; its entry class remains `godog`.

`src/engine/core.hpp` and `core.cpp` are generated by the checked-in
`tools/TranslateCore.java` from the Java desktop sources. Class and method
boundaries, constants, arithmetic order and the original script are retained.
Platform substitutions and omitted, unused paths are described in
`../documentation/native-port.md`. This repository does not claim new ownership
of the original artwork or assign a new license to the recovered code.

The asset loader was adapted from the user's Forward preservation workspace:

- Repository: `preservation-forward-by-komplex`
- Inspected HEAD: `b301e361c21b212ce60f415643a989ab168a8305`
- Source: `cpp-offline/src/assets/original_asset_loader.cpp`
- Source SHA-256: `90cd4668a378e8e841c3276640ebb18eda640f44dd6da0ab4d782b16d9b732ab`
- Adaptations: namespace/header paths, a self-contained pair of asset structures,
  a single stb_image implementation using the newer vendored header, and native
  source formatting.

No Forward scene engine, soundtrack or normalized media is used. Godog's ASE
loader, spline tracks, software rasterizers and XM mixer are translated from its
own Java reference. The packaged 47 assets are exact copies of
`java-desktop/assets/`, already verified against `original/GODOG.ZIP`.

The stb_image revision, hashes and license are recorded in `vendor/stb/`.
SDL2 and zlib are external build dependencies. The local macOS package includes
the installed SDL runtime libraries and their licenses. On this machine SDL2 is
provided by SDL2-compat, which also dynamically loads SDL3; both libraries are
included. This is still an application using the SDL2 API.
